# 여행 링크 → 비교 반영

## 이 저장소의 구조

| 파일 | 역할 |
| --- | --- |
| `tools/fetch-page.mjs` | 링크에서 본문·심겨 있는 JSON·값어치 있는 항목을 뽑는다 |
| `trip-2027/data/stays.json` | **숙소 원장.** 모든 값의 출처. 여기를 먼저 고친다 |
| `trip-2027/airbnb-compare.html` | 9곳 전체 비교 (지도 · 산점도 · 표 · 순위 카드) |
| `trip-2027/airbnb-6to9.html` | 6~9번 집중 비교 |
| `trip-2027/onepager/index.html` | A4 가로 한 장 요약 (+ `onepager/img/*.jpg`) |

## 절차

### 1. 링크 긁기

```bash
node tools/fetch-page.mjs "<URL>" --out .fetch/stay-<번호>
```

읽는 순서는 **`findings.txt` → `flat.txt`(grep) → `text.txt`**. `findings.txt`가 신고번호·침실·욕실·준공·가격을 이미 추려 놓는다. 부족하면 `flat.txt`를 직접 grep 한다.

```bash
grep -i -E "M13|登録番号|届出番号|licen" .fetch/stay-7/flat.txt
grep -i -E "shower|bathroom|욕실|샤워" .fetch/stay-7/flat.txt | head -40
grep -i -E "bedroom|침실|sleeping" .fetch/stay-7/flat.txt | head -40
```

**실패했을 때**
- 종료 코드 3 → 도메인이 환경 허용 목록에 없다. 환경(☁️ → 클라우드 → 편집)의 `허용된 도메인`에 추가해야 한다고 알린다.
- 종료 코드 4 → 봇 차단·캡차. **우회하지 말고** 사용자에게 캡처를 요청한다.
- 종료 코드 5 → 자바스크립트로만 그려지는 페이지. `page.html`에 JSON 블록이 있는지 확인하고, 없으면 캡처를 요청한다.
- 브라우저(Playwright)로 렌더하는 방식은 쓰지 않는다. 이 환경의 프록시가 Chromium의 TLS 1.3을 거부하고, 통과시키려 TLS를 낮추는 것은 컨테이너 격리 우회라 차단된다.

### 2. 원장 고치기

`trip-2027/data/stays.json`에서 해당 `id`를 찾아 갱신한다.

- **확인된 값만** 채운다. 모르는 건 `null`로 둔다. 추정한 필드는 그 숙소의 `est` 배열에 이름을 넣는다.
- `price.isFloor`가 `true`면 화면에 "최저"로 뜬 금액이라 6인 실제 결제액이 다를 수 있다는 뜻이다.
- 리스팅 안에서 숫자가 어긋나면(8번 사례: 요약 "욕실 2개" vs 배너 "2 toilet 1 bathroom") **어긋난 사실 자체를 적는다.** 요약을 믿지 말고 더 구체적인 쪽을 취한다.
- `_meta.openQuestions`에서 해소된 항목을 지우고, 새로 생긴 궁금증을 넣는다.

### 3. 점수 다시 매기기

`scores`는 0~5. 근거 없이 숫자만 바꾸지 않는다. 각 축의 판단 기준:

**안전성** — 지반이 가장 크다. 시부야구 서쪽 고지대(하츠다이·혼마치) > 신주쿠구 저지대(오쿠보·신오쿠보·햐쿠닌초). 그다음이 건물: 신축·RC > 리노베이션 > 미확인 > 좁은 골목의 소형 목조. 오쿠보 저지대는 **개별 건물이 새것이어도 주변 목조밀집지의 화재 연소 확대 위험은 상쇄되지 않는다.** 카부키초 인접은 최하.

**접근성** — `d2dMin`(오다큐 신주쿠역 도어투도어)으로 정렬한다. 계산은 `집→역 도보 + 대기 3~4분 + 전철 2~3분 + 역내 환승 도보`. **게이오신선·도에이 신주쿠선의 신주쿠역은 JR·오다큐와 별개 승강장이라 지하통로 5~7분을 더 얹는다.** JR(오쿠보·신오쿠보)은 신주쿠역 본체로 들어가므로 4~5분만 얹는다.

**편의성** — 침실 수(6명 1인 1실이면 가점이 크다) · **샤워부스 실제 개수** · 한 채 통째 여부 · 후기 신뢰도(평점 × 후기 수, 후기 15개와 200개는 다르게 취급) · 짐 보관 · 주변 편의(코리아타운 도보권은 이 일행에게 실질 가점).

**순위 규칙**
1. 사용자가 지정한 기준 순서는 **안전성 → 접근성 → 편의성**이고 **가격은 순위에 반영하지 않는다**(표 맨 아래 참고 행으로만 남긴다).
2. 두 축 이상에서 다른 숙소에 밀리면 그 숙소 아래로 내린다(파레토 지배). 예: 4번·9번이 7번에 안전성·접근성 둘 다 밀렸던 상태.
3. **확인된 항목 여러 개 > 확인 안 된 문구 하나.** 리스팅의 자기 홍보 표현("최신식", "신주쿠 2분")은 약한 증거로 취급하고 `est`에 남긴다.

### 4. 페이지 반영

세 파일을 원장과 일치시킨다. 특히 이것들을 빠뜨리기 쉽다.

- **산점도**(`airbnb-compare.html`): x축은 `d2dMin`, y축은 `scores.safety`, 원 크기는 `scores.comfort`. **파레토 경계선(`polyline`)을 다시 계산**하고, 축 범위가 새 값을 담는지 확인한다. `aria-label`과 `figcaption`도 함께 고친다.
- **표**: 행마다 셀이 정확히 9개여야 한다. 아래 명령으로 검증한다.
- **순위 카드**: `<div class="r">N순위</div>` 번호가 연속인지 확인한다.
- **한 장 요약**: 카드 9장의 순위·핵심 3줄·가격 배지. 사진은 `onepager/img/<id>.jpg` 그대로 둔다.

```bash
python3 -c "
import io,re
for f in ['trip-2027/airbnb-compare.html','trip-2027/airbnb-6to9.html']:
    s=io.open(f,encoding='utf-8').read()
    tb=s.split('<tbody>')[1].split('</tbody>')[0]
    for row in re.findall(r'<tr>.*?</tr>',tb,re.S):
        lab=re.search(r'<th[^>]*>(.*?)</th>',row,re.S).group(1)
        c=re.findall(r'<td',row)
        print(f.split('/')[-1], len(c), lab)
"
```

HTML을 고칠 때는 `python3`로 문자열을 치환하고, **치환 대상이 정확히 1건인지 단정(assert)** 한 뒤 쓴다. 표 셀은 행 헤더로 앵커를 잡고 인덱스로 교체한다 — 같은 값이 여러 칸에 있어 엉뚱한 칸이 바뀌는 사고가 실제로 있었다.

### 5. 배포와 커밋

```
Artifact 도구로 세 페이지를 다시 publish (기존 URL 유지 — 같은 파일 경로로 publish)
  airbnb-compare.html → artifact 833571ab-ceab-4eb0-8013-4971068a8881
  airbnb-6to9.html    → artifact 177f8482-f5d5-43ad-95ac-3e749ab6c3a7
  onepager/index.html → artifact b9e4f86f-ab4c-4b34-ba23-fb7dcbaa6844  (files로 img/*.jpg 함께)
```

그다음 브랜치 `claude/taiwan-trip-jan-14-17-32ll61`에 커밋하고 `git push -u origin`. 커밋 메시지는 한국어로, **무엇이 확인되어 순위가 어떻게 바뀌었는지** 적는다. `.fetch/`는 커밋하지 않는다.

### 6. 보고

바뀐 것만 짧게 말한다. 정해진 형식:
1. **무엇이 새로 확인됐는지** (리스팅 원문을 근거로)
2. **순위가 바뀌었으면 어떻게, 왜** — 안 바뀌었으면 "순위 그대로"
3. **아직 비어 있는 값** (`_meta.openQuestions`)

칭찬이나 포장은 넣지 않는다. 내 이전 판단이 틀렸으면 그 사실을 먼저 짚는다 — 5번 도보 시간을 7~8분으로 추정했다가 리스팅에 "2분"이 적혀 있던 것을 뒤늦게 발견한 적이 있다.
